# macOS on-device AI via Apple's Foundation Models framework (macOS 26 "Tahoe" / Apple Intelligence)

Research date: 2026-10-27. Framework shipped with iOS/iPadOS/macOS 26 in September 2025; WWDC26 (June 2026) announced a second generation (iOS/macOS 27) that changes several facts below. Each finding is tagged **[26]** (first generation, shipped Sept 2025) or **[27]** (announced WWDC26, June 2026; support pages now list macOS 27 "Golden Gate" as current). Anything older than June 2025 is pre-framework.

---

## Key question 0: Hard facts about the on-device model (size, context, languages, eligibility, availability states, latency, rate limits, image input)

### Takeaway
The macOS 26 on-device model is a ~3B-parameter, 2-bit-quantized text-only LLM with a per-session 4,096-token context (everything counts: instructions, prior turns, tool schemas, tool output, generated output), reachable only on Apple-silicon Macs with Apple Intelligence on and a supported Siri/device language. It is free, offline, and un-rate-limited in the foreground/on power, but is throttled when a process is in the background on battery. Image input arrives only with the iOS/macOS 27 model.

### Cited Findings
- **Parameter count / quantization [26]:** "The on-device model we just used is a large language model with 3 billion parameters, each quantized to 2 bits." — [WWDC25 "Meet the Foundation Models framework"](https://developer.apple.com/videos/play/wwdc2025/286/)
- Apple's tech report describes "a compact, approximately 3-billion-parameter model optimized to run efficiently on Apple silicon" plus a server mixture-of-experts model; on-device design uses "KV-cache sharing, 2-bit quantization-aware training"; models "are designed to support 16 different languages" (v1 17 Jul 2025, v3 27 Aug 2025). — [Apple Intelligence Foundation Language Models Tech Report 2025, arXiv 2507.13575](https://arxiv.org/abs/2507.13575); [Apple ML Research page](https://machinelearning.apple.com/research/apple-foundation-models-tech-report-2025)
- **Not for world knowledge:** "It's not designed for world knowledge or advanced reasoning, which are tasks you might typically use server-scale LLMs for." Optimised "for use cases like summarization, extraction, classification." "Device scale models require tasks to be broken down into smaller pieces." — [WWDC25 session 286](https://developer.apple.com/videos/play/wwdc2025/286/)
- **Context window = 4,096 tokens per session [26]:** Apple engineers' code-along Q&A (25 Sept 2025): "What's the context limit for prompts?" → "4096 tokens." Limit is per session, no cap on number of sessions; input + output both count; tool descriptions, tool responses, `@Generable` schemas and `@Guide` descriptions all count. — [Code-along Q&A notes gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74)
- Apple Developer Forums reply: "The framework has a context size limit, which is 4096 as of today, meaning that the token number of the whole session needs to be no more than 4096." Workaround: "Summarize your previous session, and share your summary in a new session to get you a fresh 4096 collection of tokens." — [Apple Developer Forums thread 806542](https://origin-devforums.apple.com/forums/thread/806542?answerId=865200022)
- WWDC25 deep dive: "If your session exceeds the available context size, it will throw an error, which you should be prepared to catch" (`LanguageModelSession.GenerationError.exceededContextWindowSize`); recovery sample rebuilds a session from a condensed transcript keeping the instructions entry. — [WWDC25 "Deep dive into the Foundation Models framework" (301)](https://developer.apple.com/videos/play/wwdc2025/301/)
- **Context becomes hardware-dependent [26.4/27]:** iOS 26.4 added `model.contextSize` and `tokenCount(for:)`; WWDC26 example shows `contextSize` returning `8192`; a `usage` property reports input/output/cached/reasoning tokens. — [WWDC26 "What's new in the Foundation Models framework" (241)](https://developer.apple.com/videos/play/wwdc2026/241/); corroborated by [drobinin.com, 16 Jun 2026](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- **Device eligibility:** "the model can only run on Apple Intelligence-enabled devices in supported regions." — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/). Apple's support page lists Macs with M1 or later (plus "MacBook Neo (A18 Pro)"), iPhone 15 Pro/16+/Air, iPad mini (A17 Pro) and M-series iPads; storage up to 14 GB on newer devices, up to 8 GB on others; requires "Device language and Siri language set to the same supported language"; features do not work in mainland China. — [Apple Support: Apple Intelligence requirements](https://support.apple.com/en-us/121115)
- **Supported languages (macOS 27 list, 16):** English, Danish, Dutch, French, German, Italian, Norwegian, Portuguese, Spanish, Swedish, Turkish, Vietnamese, Chinese (Simplified), Chinese (Traditional), Japanese, Korean. — [Apple Support 121115](https://support.apple.com/en-us/121115). Eight of these (Danish, Dutch, Norwegian, Swedish, Portuguese (Portugal), Turkish, Traditional Chinese, Vietnamese) were added in November 2025 per an Apple forum reply. — [Apple Developer Forums thread 805378](https://developer.apple.com/forums/thread/805378)
- **Language gating hurts availability:** Thread "Foundation Models unavailable for millions of users due to device language restriction" (Oct 2025): `SystemLanguageModel.isSupported` returns false for Catalan, Polish, Finnish, Czech, Hungarian, Greek, Romanian etc.; Apple's reply: Apple Intelligence follows the *Siri* language setting, not system language; developers can call `supportsLocale(_:)`, which returns true when a close supported language exists (e.g., Spanish for Catalan). — [Apple Developer Forums thread 805378](https://developer.apple.com/forums/thread/805378)
- `SystemLanguageModel.default.supportedLanguages` exists; `GenerationError.unsupportedLanguageOrLocale` is thrown for unsupported input. — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)
- **Availability API:** "Availability is a two case enum that's either available or unavailable. If it's unavailable, you also receive a reason." — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/). The three unavailable cases in practice: device not eligible, Apple Intelligence off, model still downloading (`modelNotReady`); "The concrete type behind that `.unavailable` reason has shifted across iOS 26 dot-releases." — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/). `SystemLanguageModel` is `Observable`, so SwiftUI re-renders when availability changes; one shared system model that the OS loads/unloads; no app-size increase; Simulator works on macOS 26 if Apple Intelligence is on for the host Mac. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74)
- **Latency:** `prewarm()` saves "about 500 ms" if the model was not already loaded, no visible difference if cached. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74). Shipped apps pay a "one-to-two-second cold start" vs "about a second" in demos; fix is to create the session when the screen appears. — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/). "Each token in your instructions and prompt adds extra latency"; keep tool descriptions to ~one sentence. — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/). Instruments has a Foundation Models profiling template (Xcode 26) and in Xcode 27 reports time-to-first-token and tokens/sec. — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/); [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- **Rate limits:** Apple engineers: "There is no rate limit when your device is connected to power" or when the app runs in the foreground. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74). Apple Frameworks Engineer (June 2025): rate limiting applies when the device is "on battery AND the process is running in the background"; Safari extensions count as background; workaround is `respond` instead of `streamResponse` because streaming "uses more power and hits the limit sooner". The error surfaced as "Safety guardrail was triggered after consecutive failures during streaming" while Console.app showed a rate limit; the reporter also hit it on power (known issue 153216632, FB18332004). — [Apple Developer Forums thread 789788](https://developer.apple.com/forums/thread/789788). Another report of "Client rate limit exceeded" generating long text, DevRel asked whether it ran in background. — [Apple Developer Forums thread 793787](https://developer.apple.com/forums/thread/793787). A documented `LanguageModelError.rateLimited(_:)` case exists in the (27) API. — [Apple docs: rateLimited(_:)](https://developer.apple.com/documentation/foundationmodels/languagemodelerror/ratelimited(_:).md)
- **Image input:** [26] model is text-in/text-out; Apple pointed developers to Vision for OCR and Speech for audio. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74). Hugging Face (Nov 2025): Apple's model "doesn't currently support sending images with prompts." — [Hugging Face AnyLanguageModel blog](https://huggingface.co/blog/anylanguagemodel). [27] "a new on-device model, rebuilt from the ground up" gains vision: `Attachment(UIImage(...))` in prompts; supports UIImage, NSImage, CGImage, Core Image, CVPixelBuffer and file URLs; "larger images will consume more tokens and incur more latency." — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- **Sampling / determinism:** default random sampling; `GenerationOptions(sampling: .greedy)` is deterministic only for one model version — "When the model is updated as part of an OS update, your prompt can definitely give different output, even when using greedy sampling." — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)
- **Error API change:** `GenerationError.exceededContextWindowSize`, `.guardrailViolation`, `.refusal` are deprecated in OS 27 in favour of `LanguageModelError`. — [joeblau/voice PR #102](https://github.com/joeblau/voice/pull/102)

### Inferences
- For a short-task assistant on macOS 26 the practical envelope is: one task per session, prompt + instructions + schema well under ~3,000 tokens to leave room for output, text only, and never from a background helper process on battery without expecting throttling.
- Because availability depends on the Siri language (not system language) and region, any product should treat the on-device model as optional and probe `availability` at runtime rather than at install.

### Gaps
- Apple's official `UnavailableReason` documentation page and the "Improving the safety of generative model output" page returned empty bodies in this harness; case names (`deviceNotEligible`, `appleIntelligenceNotEnabled`, `modelNotReady`) are from secondary sources and Apple sample code, not verified against the page text.
- No Apple document states numeric background rate-limit thresholds or cooldown durations.
- Exact macOS-specific latency numbers (tokens/sec on M1 vs M4) were not found in a citable source.

## Key question 1: Which concrete apps ship Foundation Models as an on-device first rung, and do any fall back to a cloud model or user key? How do they decide?

### Takeaway
Apple's September 2025 showcase names ~21 shipping apps (several Mac-native: OmniFocus 4.8, Agenda, Stuff, VLLO, Signeasy, Essayist, Detail), all using the on-device model for small structured tasks (classify, extract, generate sub-tasks, summarise entries). I found no shipping app that documents an automatic on-device-then-cloud fallback decision rule; the fallback story is instead carried by libraries (AnyLanguageModel, OpenFoundationModels) and, from OS 27, by Apple's own `LanguageModel` protocol with `PrivateCloudComputeLanguageModel` and Anthropic/Google packages.

### Cited Findings
- **Apple Newsroom showcase (Sept 2025; page carries an UPDATE dated 29 Sept 2025):** apps and uses — SmartGym (text description → structured routine, coaching messages, workout summaries), Stoic (journaling prompts from recent entries, summaries, search; "generated entirely on device"), SwingVision, 7 Minute Workout (natural-language workout builder), Gratitude (weekly summaries, affirmations), Train Fitness (suggest substitute exercise), Motivation (categorise quotes), Streaks (suggest and auto-categorise tasks), Wakeout!, CellWalk (explain terms; uses tool calling to ground answers in app data), Grammo, Lil Artist (stories + ImageCreator), Vocabulary (group words into themes), Platzi (Q&A about current lesson), Stuff by Austin Blake (parse dates/tags/lists while typing; Listen Mode speech→tasks; Scan Mode handwriting→tasks), VLLO by Vimosoft (music/sticker suggestions per scene with Vision; Mac screenshots shown), Signeasy (summarise documents, answer document questions), Agenda ("Ask Agenda" answers questions about notes with links), Detail: AI Video Editor (outline→teleprompter script, titles/descriptions/hashtags), Essayist (PDF → citations with Vision), OmniFocus 4 (generate projects/next steps, suggest tags). Apple states inference is "free of cost", works offline, with guided generation "which ensures that the models respond with a consistent format." — [Apple Newsroom](https://www.apple.com/newsroom/2025/09/apples-foundation-models-framework-unlocks-new-intelligent-app-experiences/); coverage: [MacStories](https://www.macstories.net/news/apple-highlights-apps-using-its-foundation-models-framework/), [Neowin](https://www.neowin.net/news/apple-highlights-third-party-apps-using-its-on-device-apple-intelligence-models/), [Gigazine 30 Sept 2025](https://gigazine.net/gsc_news/en/20250930-how-developer-use-apple-local-ai-ios-26)
- **OmniFocus 4.8 for Mac (15 Sept 2025):** Omni Automation plug-ins can query Apple's on-device model "only on hardware that supports Apple Intelligence"; example plug-in generates sub-tasks for a selected task; Omni said the APIs "will soon be coming to all of our other apps as well." — [Omni Group blog "Ready for OS 26"](https://www.omnigroup.com/blog/ready-for-os-26); [OmniFocus for Mac 4.8 release notes](https://www.omnigroup.com/releasenotes/omnifocus/P30); [9to5Mac, 15 Sept 2025](https://9to5mac.com/2025/09/15/omnifocus-4-8-apple-intelligence-support/)
- **Activas (indie, Brian Hough):** HealthKit + on-device model, "entirely offline" health insights/chat. — [MacStories iOS 26 review, "Foundation Models, Apps, and Shortcuts"](https://www.macstories.net/stories/ios-and-ipados-26-the-macstories-review/8)
- **Craft:** a secondary roundup claims Craft uses the on-device model as an offline notes assistant; unverified against Craft's own release notes. — [Elephas roundup](https://elephas.app/resources/apple-intelligence-apps)
- **FileMaker:** Claris documented calling Apple Foundation Models from FileMaker on macOS. — [Medium: Using Apple Foundation Models in FileMaker](https://medium.com/transforming-digital/using-apple-foundation-models-in-filemaker-ba25d6c80739)
- **Open-source macOS uses:** `apple-fm-bootstrap` wraps the on-device model in a single file (macOS 26+, "zero download, zero tokens"). — [github.com/esaruoho/apple-fm-bootstrap](https://github.com/esaruoho/apple-fm-bootstrap). A blog shows exposing the macOS model as a local OpenAI-compatible API. — [zhixian.io](https://zhixian.io/en/posts/apple-foundation-model-local-api/). `joeblau/voice` uses the on-device model for topic labels and boundary confirmation, and tracks the OS-27 error renames. — [joeblau/voice PR #102](https://github.com/joeblau/voice/pull/102)
- **Fallback libraries:**
  - **AnyLanguageModel** (Mattt / Hugging Face, 20 Nov 2025): "Swap your `import` statement, keep the same API"; backends Apple Foundation Models, Core ML, MLX, llama.cpp, Ollama, OpenAI, Anthropic, Gemini, Hugging Face Inference Providers; lists Foundation Models "as a system-level fallback in hybrid app designs"; extends the API with image input Apple lacked. — [Hugging Face blog](https://huggingface.co/blog/anylanguagemodel); [github.com/mattt/AnyLanguageModel](https://github.com/mattt/AnyLanguageModel); [InfoQ, Nov 2025](https://www.infoq.com/news/2025/11/anylanguagemodel)
  - **OpenFoundationModels / AnyFoundationModels** (1amageek): "100% API compatibility" reimplementation with Claude, OpenAI, Ollama, MLX backends behind build traits; examples wrap Apple's framework in `#if canImport(FoundationModels)` and check `isAvailable`. — [Swift Forums announcement](https://forums.swift.org/t/openfoundationmodels-apple-compatible-foundation-models-api-with-multi-provider-support/82168); [Swift Package Registry](https://swiftpackageregistry.com/1amageek/OpenFoundationModels)
  - **foundation-openai** (AreroKetahi): `ChatGPTLanguageModel` usable in `LanguageModelSession`. — [Swift Package Registry](https://swiftpackageregistry.com/AreroKetahi/foundation-openai)
  - Recommended decision pattern in community skill repos: check `SystemLanguageModel.default.isAvailable` → try MLX local → final cloud fallback. — [swift-ios-skills reference](https://tessl.io/registry/dpearson2699/swift-ios-skills/3.6.0/files/skills/apple-on-device-ai/references/mlx-swift.md)
- **[27] First-party fallback path:** new `LanguageModel` protocol lets "both local and servers models back a LanguageModelSession"; `SystemLanguageModel` and `PrivateCloudComputeLanguageModel` conform; "Anthropic, and Google are both publishing Swift packages"; open-source `CoreAILanguageModel` and `MLXLanguageModel`; sessions expose `usage` token counts; Apple warns "never store private keys in your app binary", use OAuth + Keychain. Dynamic Profiles can switch a session's model/reasoning level at runtime (`.model(states.privateCloudCompute)`). — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/). A consultant calls the swap "on paper, a one-line change" but notes the developer still "owns auth, billing, Keychain storage, and App Attest". — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)

### Inferences
- Shipped first-generation apps chose tasks that fit 4K tokens and guided generation (classification, sub-task generation, short summaries); none of the showcased apps advertises a cloud fallback, consistent with Apple's framing of the framework as free/offline/private.
- The realistic 2026 architecture for an app like OpenClicky is: probe availability → on-device for short rewrite/classify/extract → on failure (`unavailable`, context overflow, guardrail, rate limit) route to the user's own key or a hosted model, using either Apple's `LanguageModel` protocol (OS 27) or AnyLanguageModel for OS 26 parity.

### Gaps
- No shipping macOS app was found that publicly documents its on-device-vs-cloud decision rule (e.g., "try on-device, fall back to OpenAI after error X"). Developer blogs describe the pattern; apps do not.
- Exact versions/dates for Agenda, Stuff, Signeasy, Essayist releases were not retrieved; only Apple's September 2025 showcase date and OmniFocus 4.8 (15 Sept 2025) are confirmed.

## Key question 2: What have developers reported about quality for short tasks vs failures?

### Takeaway
Developers and one academic audit agree the model is reliable for constrained short tasks when `@Generable`/`@Guide` pin the output shape, and unreliable for anything needing facts, arithmetic, or long input: it confabulates on 69% of false-premise questions, over-refuses 18% of benign prompts, and its guardrails fire on innocuous text (improved in iOS 26.4). The specific failure "answers the question instead of rewriting it" was not found in a citable source.

### Cited Findings
- **Academic audit (Aug 2026):** "Confidently Wrong, Silently So" audits "the developer-accessible on-device foundation model" (~3B, queried on a commodity laptop via the FoundationModels framework): confabulates on 69% of false-premise questions; refuses 18% of entirely benign inputs; self-reported confidence AUROC 0.47, ECE 70 ("worst among comparable small models"); user-visible features separate right from wrong at AUROC 0.55; a black-box consistency wrapper cut confident confabulation 75%→3% and raised selective accuracy 43%→83%. — [arXiv 2608.23663](https://arxiv.org/abs/2608.23663)
- **Practitioner report (16 Jun 2026):** model "can invent numbers"; "paraphrase data into something plausible and wrong"; "Raw rows invite arithmetic the model handles poorly"; the model "can skip a registered tool entirely"; fixes: tools return pre-formatted strings the model quotes verbatim, constrain arguments with `@Generable`/`@Guide` enums. — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/)
- **Tool-calling capacity:** Apple engineers' rule of thumb: 3–4 distinct tools per session; use detailed descriptions and emphasis words such as "MUST" to stop the model ignoring tools. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74)
- **Guardrails strict / false positives:** "Detected content likely to be unsafe" on ordinary prompts; Apple: guardrails are strict, prompt language affects sensitivity; log `LanguageModelSession.logFeedbackAttachment` and file feedback. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74). Safari-extension developer reported "false guardrail violations on innocuous prompts"; another developer saw guardrail violations in iOS 26 beta 2 that beta 1 passed. — [Apple Developer Forums 789788](https://developer.apple.com/forums/thread/789788). `guardrailViolation` and `unsupportedLanguageOrLocale` are non-recoverable (retrying "wastes battery"); `exceededContextWindowSize` is recoverable by rebuilding the session. — [drobinin.com](https://drobinin.com/consulting/foundation-models-apple-intelligence/putting-apple-foundation-models-in-a-real-app/). Apple: iOS 26.4 reduced guardrail false positives, more improvements in iOS 27. — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- **Guided generation quality:** constrained decoding "fundamentally guarantees structural correctness"; "Guided Generation tends to improve model accuracy" and speeds inference; "It will never make up an unexpected field!"; properties generate in declaration order, so put summaries last. — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/); [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)
- **Shortcuts-level observations (June 2025, Federico Viticci):** on-device model refused "I'm sorry, but I can't describe images directly"; both Apple models failed on 43 RSS items citing context length while ChatGPT succeeded; the on-device model handled entity filtering (GoodLinks articles about Liquid Glass) well. — [MacStories](https://www.macstories.net/notes/i-have-many-questions-about-apples-updated-foundation-models-and-the-great-use-model-action-in-shortcuts/)
- **Long-input workaround guidance from Apple:** split inputs, summarise, new session. — [Apple Developer Forums 806542](https://origin-devforums.apple.com/forums/thread/806542?answerId=865200022); [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)

### Inferences
- The right contract for an on-device first rung is "schema-constrained, no facts required": rephrase-with-`@Generable`-string, intent classification with an `anyOf` enum, JSON extraction with `@Guide` ranges. Open-ended Q&A about on-screen text is where it fails (confabulation, context overflow), so that should route to a larger model.
- Because guardrail false positives cluster around innocuous-but-sensitive text (health, names, money), rewrite features on arbitrary user text need a silent cloud/key fallback rather than an error toast.

### Gaps
- No citable report of the "asked to rewrite, answered instead" failure for Apple's model; it is a known small-model behaviour but no source documents it for Foundation Models.
- No published benchmark comparing Foundation Models rewrite quality to Writing Tools or to GPT-class models on the same prompts.

## Key question 3: Shortcuts "Use Model" action and on-device / Private Cloud Compute / ChatGPT routing; is PCC reachable by third-party developers?

### Takeaway
The "Use Model" action lets the *user* pick On-Device, Private Cloud Compute (now shown as "Cloud" / "Cloud Pro" with extended context) or the ChatGPT extension; routing is a manual choice, not automatic. In the 2025 framework, third-party developers got only the on-device model; WWDC26 added `PrivateCloudComputeLanguageModel` (32K context, reasoning levels, no API cost under 2M first-time downloads, entitlement required) for OS 27.

### Cited Findings
- Apple's Mac Shortcuts guide: "On-Device uses the on-device Apple Intelligence model to handle simple requests without the need for a network connection"; "Private Cloud Compute uses Apple's Private Cloud Compute to handle complex requests while protecting your privacy"; "Extension Model uses ChatGPT to handle your requests." Newer pages list "Cloud" and "Cloud Pro", the latter with "extended context for larger tasks than Cloud." — [Apple Support: Use Apple Intelligence in Shortcuts on Mac](https://support.apple.com/guide/shortcuts-mac/mchl91750563/mac); [iPhone/iPad version](https://support.apple.com/guide/shortcuts/tpg3vrvwmclv)
- Output types: Automatic, Text, Number, Date, Boolean, List, Dictionary, plus native Shortcuts entity types; entities are converted to JSON via App Intents; "Follow Up" enables a conversational mode; ChatGPT option uses the user's OpenAI account via the Settings extension. — [MacStories, June 2025](https://www.macstories.net/notes/i-have-many-questions-about-apples-updated-foundation-models-and-the-great-use-model-action-in-shortcuts/); [Club MacStories Automation Academy on GPT-5 in Use Model](https://club.macstories.net/posts/automation-academy-apple-intelligence-gpt-5-and-the-use-model-action-in-shortcuts)
- Viticci on PCC access: "Developers only got access to the local Foundation model" (2025). Observed: on-device cannot analyse images in Shortcuts; cloud model returned identical image descriptions across days; context limits hit at 43 RSS items. — [MacStories](https://www.macstories.net/notes/i-have-many-questions-about-apples-updated-foundation-models-and-the-great-use-model-action-in-shortcuts/)
- [27] `PrivateCloudComputeLanguageModel`: "a much bigger model than the on-device models", "a 32,000 token context window", `reasoningLevel` via `contextOptions` ("Deep reasoning produces better responses in exchange for additional compute"); "No prompts are ever stored"; no auth/API keys; "available with no cloud API costs to developers who have less than 2 million first time downloads"; daily per-user allowance, higher for iCloud+ subscribers; requires an entitlement (named in the "building with Private Cloud Compute" session). — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- Developer forum question remains open on whether third-party cloud models (Claude/Gemini packages) route via PCC or directly to the provider. — [Apple Developer Forums thread 833627](https://developer.apple.com/forums/thread/833627)
- Macs also get an `fm` CLI (`fm chat`) in macOS 27 with on-device and PCC access, and a Python SDK (`apple_fm_sdk`). — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- Apple's general Apple Intelligence routing statement (pre-framework, 2024): most requests on-device, "more complex requests" to Private Cloud Compute; data "never stored or shared with Apple." — [Apple Newsroom via BusinessWire, 10 Jun 2024](https://www.businesswire.com/news/home/20240610414067/en)

### Inferences
- In Shortcuts the on-device/PCC choice is the author's, so a Shortcut can be the cheapest way to reach PCC on macOS 26 without any entitlement — but only as a user-visible automation, not from app code.
- For OS 27 apps the PCC tier is the natural "second rung" before a user-supplied key: zero cost under the download threshold, no key management, 32K context.

### Gaps
- No Apple document gives the per-user daily PCC quota numbers or the entitlement name; the "building with Private Cloud Compute" session (WWDC26) was not fetched.
- Which GPT version the ChatGPT extension uses is inconsistent across sources (GPT-4 Turbo observed June 2025; GPT-5 per later Club MacStories).

## Key question 4: What do Apple's docs and WWDC25 sessions say about tool calling, guided generation, dynamic schemas, adapters/LoRA, and the 4,096-token limit?

### Takeaway
WWDC25 defines the toolkit: `@Generable`/`@Guide` with constrained decoding; `Tool` protocol with `@Generable` arguments, parallel invocation and transcript injection; `DynamicGenerationSchema` for runtime schemas; LoRA adapters (~160 MB, per-model-version, entitlement-gated); and a session that throws `exceededContextWindowSize` when the transcript overflows (4,096 tokens, stated by Apple engineers rather than in the session transcripts).

### Cited Findings
- **Guided generation:** "two new macros, @Generable and @Guide"; "constrained decoding works by masking out the tokens that are not valid"; primitives, arrays, nested and recursive types; `@Guide(.count(4))`, `.range(1...10)`, `.anyOf`, regex guides; streaming returns `PartiallyGenerated` snapshots with all-optional properties. — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/); [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)
- **Tool calling:** tools conform to `Tool` with `name`, `description`, `@Generable Arguments`, `call(arguments:) -> ToolOutput`; "tool calling is built on guided generation to ensure that the model will never produce invalid tool names or arguments"; "Tools must be attached at session initialization"; "a tool can be called multiple times for a single request... your tool gets called in parallel"; tool name/description "are put verbatim in your prompt"; tool output enters the transcript; the session blocks until the tool returns. — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/); [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/). iOS 26.1 beta exposes the session transcript inside a tool. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74)
- **Dynamic schemas:** `DynamicGenerationSchema(name:properties:)`, `arrayOf`, `referenceTo`; validated via `GenerationSchema(root:dependencies:)` which "can throw errors if there are inconsistencies"; output is `GeneratedContent` read with `value(_:forProperty:)`. — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/). Schemas are included in the prompt and consume tokens; `includeSchemaInPrompt` exists for large structures. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74)
- **Adapters:** built-in content-tagging adapter via `SystemLanguageModel(useCase: .contentTagging)` ("tag generation, entity extraction, and topic detection"); custom adapters "come with significant responsibilities because you need to retrain it as Apple improves the model over time." — [WWDC25 286](https://developer.apple.com/videos/play/wwdc2025/286/). Adapter training toolkit: LoRA (frozen base, trainable low-rank matrices; rank not stated), Mac with Apple silicon and ≥32 GB or Linux GPU, Python 3.11+, ~160 MB per adapter, delivered via Background Assets not the app bundle, one adapter per system model version, entitlement `com.apple.developer.foundation-model-adapter` requested by the Account Holder; data 100–1,000 JSONL samples for basic tasks, 5,000+ for complex; optional draft model for speculative decoding; toolkit 26.0.0 is the last release and "not compatible with OS 27 and later." — [Apple: Foundation Models adapter training toolkit](https://developer.apple.com/apple-intelligence/foundation-models-adapter/)
- **Session/context:** "A LanguageModelSession is stateful... a session has a limit for how large it can grow"; recovery by rebuilding from a condensed `Transcript` keeping instructions. — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/). The number 4,096 comes from Apple engineers in Q&A and forums, not the session transcripts. — [Code-along Q&A gist](https://gist.github.com/stinger/81891077161002819c0ec233f73edc74); [Apple Developer Forums 806542](https://origin-devforums.apple.com/forums/thread/806542?answerId=865200022)
- **[27] additions:** system tools `BarcodeReaderTool`, `OCRTool` (Vision-backed) and a Spotlight search tool for "fully local Retrieval-Augmented Generation"; Dynamic Profiles; an Evaluations framework; the framework and a utilities package (transcript management, skill API, Chat Completions client) "going open source" to run "everywhere Swift runs, including Linux servers." — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)
- Human Interface Guidelines have a "Generative AI" section referenced by the deep-dive session. — [WWDC25 301](https://developer.apple.com/videos/play/wwdc2025/301/)

### Inferences
- Adapters are impractical for a small team shipping across OS versions (160 MB per model version, retrain per OS, toolkit already end-of-life for OS 27); prompt + schema engineering is the sustainable path.
- The OCR and Spotlight system tools in OS 27 are directly relevant to "answer questions about on-screen text" on macOS.

### Gaps
- Official Apple documentation text for `exceededContextWindowSize`, `guardrailViolation` and acceptable-use requirements could not be fetched (empty page bodies); the acceptable-use policy wording is therefore not quoted.
- No source gives the LoRA rank or the base model version string used by the toolkit.

## Key question 5: Accessibility-focused or older-adult-focused macOS apps using the on-device model

### Takeaway
No shipping macOS or iOS app explicitly aimed at blind, low-vision or older-adult users and built on Foundation Models was found; the closest are task apps with speech/handwriting capture (Stuff) and health chat (Activas), plus Apple's own WWDC26 guidance that classification on busy or low-battery devices must be best-effort.

### Cited Findings
- Stuff's Listen Mode (speech→tasks) and Scan Mode (handwriting→tasks) are the nearest accessibility-adjacent uses in Apple's showcase. — [Apple Newsroom](https://www.apple.com/newsroom/2025/09/apples-foundation-models-framework-unlocks-new-intelligent-app-experiences/)
- Activas offers offline health chat over HealthKit data. — [MacStories iOS 26 review](https://www.macstories.net/stories/ios-and-ipados-26-the-macstories-review/8)
- WWDC26 developer Q&A: for unavailable models (older devices, Apple Intelligence off, low battery) treat classification as "best-effort with retry" rather than expecting an immediate background result under thermal pressure. — [WWDC26 session 8016](https://developer.apple.com/videos/play/wwdc2026/8016/)
- Apple frames device-language gating as a hard availability barrier affecting non-supported-language users. — [Apple Developer Forums 805378](https://developer.apple.com/forums/thread/805378)

### Inferences
- The accessibility niche on top of Foundation Models appears open as of October 2026; the framework's constraints (eligibility, language, 4K context, guardrails) make a cloud/key fallback essential for a population that often runs older hardware.

### Gaps
- Searches for "Foundation Models" with VoiceOver, screen reader, seniors, dementia and accessibility returned no app; App Store descriptions were not searchable from this harness, so a small indie app could exist unindexed.

## Key question 6: Open-source Swift projects demonstrating Foundation Models with cloud fallback

### Takeaway
No single repository implements a turnkey "SystemLanguageModel then OpenAI" fallback; the ecosystem instead offers API-compatible multi-backend libraries (AnyLanguageModel, OpenFoundationModels/AnyFoundationModels, foundation-openai, MLXFoundationModels) and, in OS 27, Apple's own `LanguageModel` protocol with Anthropic/Google packages, so the fallback is a few lines of availability/error branching the app writes itself.

### Cited Findings
- AnyLanguageModel — drop-in import swap, nine backends, Apple FM as "system-level fallback in hybrid app designs". — [Hugging Face blog, 20 Nov 2025](https://huggingface.co/blog/anylanguagemodel); [github.com/mattt/AnyLanguageModel](https://github.com/mattt/AnyLanguageModel); [Swift Package Registry: huggingface/AnyLanguageModel](https://swiftpackageregistry.com/huggingface/AnyLanguageModel)
- OpenFoundationModels (1amageek) — "actual Apple system models (e.g. SystemLanguageModel.default) are only available when running on supported devices"; AnyFoundationModels bundles Claude/OpenAI/Ollama/MLX via traits; examples check `isAvailable`. — [Swift Forums](https://forums.swift.org/t/openfoundationmodels-apple-compatible-foundation-models-api-with-multi-provider-support/82168); [Swift Package Registry](https://swiftpackageregistry.com/1amageek/OpenFoundationModels)
- foundation-openai (AreroKetahi) — bridges FoundationModels APIs to OpenAI-compatible endpoints. — [Swift Package Registry](https://swiftpackageregistry.com/AreroKetahi/foundation-openai)
- MLXFoundationModels — MLX bridge but requires the OS 27 SDK. — [Medium: MLX first-class in Apple's AI stack](https://medium.com/@nuthalapativarun/mlx-is-now-a-first-class-citizen-in-apples-ai-stack-run-any-hugging-face-model-through-foundation-9dfb8dad2191)
- genkit_foundation_models (Dart/Flutter Genkit plugin for Apple's on-device model). — [pub.dev](https://pub.dev/packages/genkit_foundation_models)
- Community fallback recipe: `SystemLanguageModel.default.isAvailable` → MLX → final cloud fallback. — [swift-ios-skills reference](https://tessl.io/registry/dpearson2699/swift-ios-skills/3.6.0/files/skills/apple-on-device-ai/references/mlx-swift.md)
- Apple's OS-27 design makes the backend a session parameter (`LanguageModel` protocol; Anthropic and Google packages; open-source `CoreAILanguageModel`, `MLXLanguageModel`; utilities package includes a Chat Completions client). — [WWDC26 241](https://developer.apple.com/videos/play/wwdc2026/241/)

### Inferences
- For macOS 26 targets, AnyLanguageModel is the lowest-friction way to write one code path that uses the system model when available and a keyed provider otherwise; for macOS 27 the first-party protocol subsumes it.

### Gaps
- GitHub code search was not available in this harness, so small sample apps that combine `availability` checks with an OpenAI client may exist but were not found; the named libraries are the verifiable results.
