## Demo storyboard (one take, 35–45 s, no narration, system audio on so the voice is heard)

1. Desktop with a real app open (a Vercel or GitHub settings page reads well). Cursor buddy visible near the pointer. (2 s)
2. Hold ⌃⌥, ask: "where do I change the production branch?" Release. The buddy flies to the setting while the voice answers. (10 s)
3. Tap ⌃ twice, type "what does this page do?", ↩. Voice answers. (8 s)
4. Click into a text field, hold fn+⌃, say one sentence, release: the sentence appears in the field. (8 s)
5. Hold ⌃⌥: "make a folder called launch and put a README in it with today's date". The island shows "Working…", the result card appears, Finder shows the folder. (12 s)
6. End on the notch panel open (Home tab) so the shortcuts are visible. (2 s)

Record with QuickTime (File → New Screen Recording, microphone on) or `screencapture -v`. Trim in QuickTime. GIF via `ffmpeg -i demo.mov -vf "fps=12,scale=960:-1" -loop 0 demo.gif`.

## Hacker News

**Title:** Show HN: OpenClicky – open-source macOS voice companion that sees your screen and points at things

**URL:** https://github.com/prasanthsasikumar/openclicky

**First comment (post it right after submitting):**

> I built this because I wanted a voice assistant on my Mac that actually knows what I'm looking at. Hold control+option, ask "where do I change the deploy branch?", and a small cursor flies to the setting while it answers out loud. Tap control twice to type instead, hold fn+control to dictate into any app, and "do work" requests (files, commands, apps) go to a Codex agent thread.
>
> It's MIT. The Mac app started from Farza's open-source Clicky and grew a backend (Hono, runs on Node or Workers) that holds the keys, an agent CLI that drives Codex over its app-server protocol, and a skills layer. Voice is OpenAI Realtime with a `point_at` tool; pointing snaps the model's guess to on-screen text via Vision OCR because the model's raw coordinates are 30–100 px off.
>
> Two ways to run it: put your own OpenAI key in ~/.openclicky/shell.json (the key rides along per request and is never stored), or self-host the backend (`backend/Dockerfile`, or `npm run dev -w backend`). Hosted accounts without a key are invite-only while I watch costs.
>
> Things I know are rough: the agent lane needs the CLI and Codex installed separately, the credit accounting for voice is per session rather than per minute, and it's Apple Silicon only. Happy to answer anything about the notch HUD, the Realtime tool-calling, or the Codex bridge.

**Answers to have ready:** where does my key go (per-request header, never logged or stored; self-host in one command); why not local models (Realtime voice has no local equivalent yet; the classic lane could take an OpenAI-compatible endpoint, PRs welcome); how is this different from HeyClicky (it's the open-source version of the idea, derived from their MIT app, not affiliated; I don't compare); privacy of screenshots (sent only while you hold the key, one screenshot per turn, to your own key's provider or the hosted backend's, never kept).
