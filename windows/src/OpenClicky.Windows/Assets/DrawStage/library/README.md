# The drawing library

Real models and planet textures the drawing stage can place with `f.model(name)` and `f.planet(name)`, matched by
`library/manifest.json`. The files are copied with the app (`Assets\DrawStage\**\*`) and served from the stage's own
virtual host, so the page loads them directly; nothing is fetched from the network at drawing time.

`manifest.json` is generated by `scripts/library/fetch-space.mjs` from the same list used to download the files.
Run that script from the repository root to restore the files:

```
node scripts/library/fetch-space.mjs
```

## Sources

- Spacecraft models (GLB): [nasa/NASA-3D-Resources](https://github.com/nasa/NASA-3D-Resources), `3D Models/`.
- Planet and Moon surface images (JPG): the same repository, `Images and Textures/`.
- `moon-ground.jpg` is the repository's "Moon - Lunar Terrain" image, kept for a Moon ground patch.

Only the files listed in the fetch script are downloaded. Curiosity Rover (MSL) is not here yet: that folder ships
only `.blend` files. Mercury, Uranus and the Sun have no whole-disc texture of that name in the repository.

NASA's GLBs are Draco-compressed (`KHR_draco_mesh_compression`). The drawing page decodes them with the decoder in
`vendor/draco/`, which is fetched only when a model needs it.
